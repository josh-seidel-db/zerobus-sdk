ZEROBUS OCAML — Async built-in client-credentials OAuth
========================================================
Date: 2026-08-11. Adds built-in OAuth to the Async runtime façade — the last of
the deferred Async parity items after live TLS was solved. The Async counterpart
of the Lwt Zerobus.create_stream / Eio Zerobus_eio.with_stream_oauth.

WHAT THIS IS
------------
- lib/async/zerobus_async.ml gains:
    mint_token ~client ~table ~client_id ~client_secret
      : client-credentials grant, POST <workspace_url>/oidc/v1/token, id/secret in
        the HTTP Basic header, request body from Zerobus_core.Config
        (grant_type=client_credentials + Zerobus scope/resource + table UC
        authorization_details). Token CACHED with expiry, refreshed ~30s early,
        guarded by the client's Io_async.Mutex (Sequencer, concurrency 1) so
        concurrent mints don't stampede the endpoint. Mirrors the Lwt reference.
    with_stream_oauth client table ~client_id ~client_secret ?options f
      : ergonomic bracket — mint -> bearer+table headers -> with_stream ~tls:true.
    oauth_available : bool   (true iff cohttp-async was present at build time).
  Client record `t` gained `mutable token_cache` + `token_cache_lock`.

PACKAGING — cohttp-async is OPTIONAL (a dune [select]), by maintainer decision
------------------------------------------------------------------------------
Built-in OAuth needs an HTTP client (cohttp-async + yojson/uri/base64). Installing
cohttp-async forces cohttp 6.0 -> 5.3 on the switch. To keep the CANONICAL fl414
switch (all other green tests) unchanged and NOT force that downgrade on gRPC-only
users, the HTTP backend is a dune [select] (mirrors the tls-async live-TLS select):
    lib/async/oauth.real.ml   (cohttp-async yojson uri base64 present) — real POST
    lib/async/oauth.dummy.ml  (absent) — honest error; caller passes a bearer via
                              with_stream's headers_provider instead.
  lib/async/dune: (select oauth.ml from (cohttp-async yojson uri base64 ->
                   oauth.real.ml) (-> oauth.dummy.ml)).
  dune-project depopts += cohttp-async yojson uri base64 (opam regenerated).
So: fl414 keeps cohttp 6.0 and oauth_available=false (dummy); a cohttp-async switch
lights up real OAuth with the SAME façade code.

COHTTP-ASYNC DE-RISK (the memory's "cohttp downgrade risk" — RESOLVED, benign)
-----------------------------------------------------------------------------
On a throwaway clone of fl414's EXACT set (async v0.16, h2 0.12, core v0.16),
`opam install cohttp-async` resolved to: async v0.16 UNCHANGED, h2 0.12 UNCHANGED,
cohttp 6.0 -> 5.3.1 + cohttp-async 5.3.0 + cmdliner 2.1->1.3. Then, on that
cohttp-5.3 config, ALL of these built + passed:
    - lib/core + lib/lwt + lib/async : build clean
    - test_driver/test_driver_lwt    : 3/3  (Lwt streaming unaffected by cohttp 5.3)
    - test_rest/test_rest_lwt        : 8/8  (the package MOST exposed to cohttp —
                                             cohttp-lwt-unix — survives the downgrade)
    - test_driver_async/test_facade_async : 3/3
So the cohttp 5.3 downgrade is API-compatible for everything the SDK uses. (Note:
on a fresh/unpinned solve cohttp-async also happily coexists with the LATEST
async v0.17 + h2 0.10 — also built + tested green — so the dep is satisfiable
either way; the select simply avoids forcing ANY change on gRPC-only users.)
